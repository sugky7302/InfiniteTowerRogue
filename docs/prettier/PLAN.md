# 導入 Prettier

## 目的

統一 TypeScript 與建置腳本的格式，提供可重複執行的格式化與檢查指令。

## 設計

1. 將 Prettier 加入開發相依套件，固定完整版本，並更新 `pnpm-lock.yaml`。
2. 使用四個空格縮排、雙引號、分號與 LF 換行。每行寬度使用 100，尾端逗號使用 `all`。
   在 `.gitattributes` 固定程式與工具設定的 LF 換行，避免 Windows 取出檔案後改回 CRLF。
3. 加入 `format` 與 `format:check` 指令。範圍包含 `src/`、`scripts/`、`tests/`、`package.json`、Prettier 設定及 VS Code 設定。
4. 排除地圖、建置輸出、快取、相依套件、鎖定檔，以及自動產生的 `src/war3map.d.ts`。
5. 加入 VS Code 擴充套件建議，並啟用 TypeScript 與 JavaScript 的存檔格式化。
6. 建立首次格式化基準。保留現有未提交修改，不改變程式行為。
7. 在 `README.md` 說明安裝、格式化、檢查與排除範圍。

## 驗證

- 執行首次格式化，再執行 `format:check`。
- 確認自動產生的宣告檔與原始地圖未被格式化。
- 執行既有單元測試。
- 執行 `pnpm run test`，驗證地圖編譯、封裝與啟動。遊戲內結果必須另行觀察，不能只用程序啟動判定通過。
- 記錄實際結果。若測試失敗，區分既有問題與本次格式修改。
