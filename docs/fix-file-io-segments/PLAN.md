# 修正：檔案讀取只讀回第一段

## 問題

英雄存檔加入後，存檔碼為 265 字元。檔案框架（`ITF1|長度|資料|檢查碼`）為 280 字元，寫入時切成 3 段，每段 96 字元。

寫入的檔案內容正確。遊戲內讀取時只讀回 96 字元（2026-11-04 確認），所以自動讀檔顯示「存檔碼無效」。手動分段輸入正常。

原因：第 2 段以後使用 `BlzSetAbilityTooltip('A0IO', BlzGetAbilityTooltip('A0IO',0)+"…", 0)` 串接。Preloader 執行檔案時，這種串接沒有生效。以前的存檔碼只有約 45 字元，只有 1 段，所以沒有發現。

## 決策

- 每段使用一個技能的第 0 級：第 0 段 `A0IO`，第 i 段 `AF01`～`AF42`。不使用串接，也不使用第 1 級以上。
- 最多 43 段（檔案框架最長 4128 字元，96 字元一段）。
- 讀取前，把 `A0IO` 設為 `ITF-MISSING`，其他技能設為 `ITF-END`。讀取後依序接到第一個 `ITF-END`，再還原全部技能的原值。
- `scripts/decode-bench.cjs` 同時接受舊格式與新格式。

## 遊戲內實驗結果（2026-11-04）

| 做法 | 結果 |
|---|---|
| 第 2 段以後以 `BlzGetAbilityTooltip(...)+` 串接 | 只讀回第 1 段（96 字元） |
| 每段寫入 `A0IO` 的不同等級（第 1 級以上） | 讀回 4128 字元。每個等級都讀到同一段，第 1 級以上不能獨立保存 |
| 每段使用不同技能的第 0 級 | 採用。遊戲內確認自動讀檔成功 |

## 驗證

- Node 與 Lua 測試：最長資料（4096 字元）來回讀寫。
- 遊戲內：英雄存檔 `-save`，重新開啟地圖，`-load` 顯示「存檔已載入」。
