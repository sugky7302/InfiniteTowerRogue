# i18n I4 實作計畫

依據 `../PLAN.md` 實作自動層與本地偏好。只修改建置產出，不修改 `maps/map.w3x/`。保留現有註解。不新增套件，不執行 Git 提交。

## 查證與設計

1. [wc3trans 作者的工具](https://github.com/tdauth/wc3trans)直接以 `_Locales/deDE.w3mod/war3map.wts` 維護地圖翻譯。[多語言原型作者的說明](https://www.hiveworkshop.com/threads/multilanguage-map-prototype-translation-tutorial.339671/)示範 Reforged 的語言資料夾與根目錄後備。此機制也能放置音效與圖片。本次只產生 WTS，不放置本地腳本或物件檔。實際用戶端選擇與後備仍待遊戲驗證。
2. 專案既有 `mdx-m3-viewer-th` 的 `parsers/w3x/wts/file.js` 明確支援 `TRIGSTR_nnn`。其 `w3i/file.js` 定義地圖名稱、作者、說明、建議人數、載入與序幕文字的位置。保留既有 WTS 編號。依排序後的翻譯鍵配置新編號。三種語言使用相同編號。物件一般檔與 Skin 檔的可翻譯修改欄位全部改成參照。執行時 Lua 表必須先由原始文字產生，避免把參照或用戶端文字當成基準中文。
3. 新增 `i18n/map/<語言>.json`。鍵採 `name`、`description`、`recommendedPlayers`、`author`、`loadingScreenText`、`loadingScreenTitle`、`loadingScreenSubtitle`、`prologueScreenText`、`prologueScreenTitle`、`prologueScreenSubtitle`。首次以原始 W3I 還原的文字建立基準；已有基準值可編輯。空白欄位保留空白，避免改變引擎預設。非空文字改為 WTS 參照。W3I 第 39 版只替換已知文字區段，其餘位元組原樣保留。地圖列表與載入畫面的參照解析待遊戲驗證。
4. 根目錄與 `zhTW.w3mod` 使用基準中文。`zhCN.w3mod`、`enUS.w3mod` 使用翻譯；缺少翻譯時警告並使用基準。其他空語言資料夾沒有檔案，不需填入內容；封裝時不會加入空資料夾。其他用戶端應讀取根目錄 WTS。未修改的內建物件文字仍由用戶端提供。
5. [FileIO 作者的原始實作](https://www.hiveworkshop.com/threads/fileio.307568/)使用 `PreloadGenStart`、`Preload`、`PreloadGenEnd` 寫入 JASS 預載檔，使用 `Preloader` 與技能提示文字讀回。[Lua 範例作者](https://xgm.guru/p/wc3/preloadinref)示範 Lua 地圖亦可執行此預載檔。檔案位於文件資料夾的 `Warcraft III/CustomMapData`。本次採短小、受限的 ASCII 資料，逐段寫入專用技能的提示文字。拒絕引號、反斜線、控制字元與路徑穿越。長度與實際讀寫權限仍待遊戲驗證。
6. 新增獨立 `src/shared/file-io/`。原生介面與 WC3 實作放在 `src/shared/wc3-def/`。建置時保留專用技能代碼。共同初始化以 `CreateUnit`、`UnitAddAbility`、`RemoveUnit` 預先載入技能，之後本地讀寫不建立 handle。讀取前放入標記，讀取後恢復提示文字；標記未變表示無檔案或讀取不可用。原生寫檔沒有成功傳回值，因此結果只能表示已送出，不能證明磁碟寫入成功。不使用立即讀回作為成功證明。
7. 偏好使用版本化字串，只接受三種正式語言。啟動時讀取；不存在、損壞或錯誤時回到 `BlzGetLocale()`。`-lang` 成功後寫入。讀取結果只套用本地 Signal。聊天訂閱與資源建立在共同流程；無 sync，無存檔碼整合。

## 實作結果

### 已實作的流程

1. `scripts/utils.ts` 在全部物件儲存後先產生 I1 至 I3 的 Lua 翻譯表，再呼叫 `scripts/i18n-locales.cjs`。後者直接改寫建置物件檔，不透過會合併技能等級的高階物件屬性。
2. 保留既有 WTS 項目。物件鍵排序後從既有最大編號加一開始配置。地圖文字接著配置。三種語言使用同一份參照表。相同輸入的編號一致；新增或刪除鍵後可以重新編號，全部產物須一起建置。
3. `i18n/map/zh-TW.json` 是地圖文字的基準來源。已有值由翻譯者維護，不會被原始 W3I 覆蓋。新增鍵才由 W3I 擷取。此次提供「無盡高塔」名稱、地圖說明、建議人數與載入文字的三種翻譯。作者沿用原始資料。序幕文字保持空白。
4. W3I 只替換十個已知文字區段。第 39 版的其他區段逐位元組保留。地圖 Lua 的 `SetMapName` 與 `SetMapDescription` 也改成相同參照，避免 `config()` 保留舊名稱。
5. 執行時表仍為原始中文與 JSON 翻譯，不包含 `TRIGSTR`。自動層先由引擎選擇用戶端語言。偏好與 `-lang` 只覆蓋可在執行時設定的文字，不改載入畫面、單位說明或技能編輯器名稱。
6. `createLocalFileIo()` 必須在共同初始化呼叫。它使用建置時保留的技能 `A0IO`。共同流程建立一個隱藏的 `hpea`，加入技能後移除單位，並設定非空的閒置提示。讀寫方法不建立單位、技能、觸發器或群組。
7. 檔案資料框架為 `ITF1|長度|資料|檢查碼`。偏好資料為 `ITR-LANG-1:<語言>`。只接受三種正式語言。檢查碼最大中間值為 2031246，已用 Node 的 `Math.fround` 檢查精確度與整數上限。
8. 正式範例在共同初始化先建立檔案模組，再以 `getI18n(files)` 建立共用服務。必須在其他模組第一次使用 `t()` 或 `getI18n()` 前完成此步驟。啟動時讀取偏好；聊天只在輸入者的本地分支寫檔。讀取結果只改本地 Signal。啟動日誌列出讀取狀態、最終語言、相對路徑，以及 `GetObjectName(A0I1)` 讀到的技能編輯器名稱。

### 檔案模組的限制

- 路徑以 `CustomMapData` 為基準，最多 120 個 ASCII 字元。子資料夾以反斜線分隔。只接受英文字母、數字、連字號、底線與句點；拒絕空路徑、絕對路徑與 `..`。
- 資料最多 4096 個受限 ASCII 字元。拒絕雙引號、反斜線與控制字元。中文或其他二進位資料須由呼叫者先編碼。這是本模組的上限，不宣稱是遊戲的完整字串上限。
- 每段資料最多 96 個 ASCII 字元。包含 JASS 語句後，每次 `Preload` 輸入仍少於 200 位元組。第一段直接設定非空框架，後續段落串接至同一個技能提示。沒有依賴引擎接受空提示文字。
- `Preload` 產生的是預載腳本。`Preloader` 執行腳本後，模組才驗證技能資料。資料檢查不能隔離遭人修改的腳本。只使用本模組管理的檔案。不要同時使用其他預載產生器；各次操作必須完整結束後再開始下一次。
- 原生寫檔沒有成功傳回值。只回報「已送出，尚未確認磁碟寫入」。沒有檔案、無法存取及無法執行預載檔，可能無法區分。讀取沒有改變標記時使用用戶端語言。
- 同次遊戲對相同路徑重新讀取，可能受到引擎的預載快取影響。不以立即讀回證明磁碟成功。必須關圖再開圖確認偏好持久性。未來存檔系統使用此模組時，仍須自行設計同步與資料驗證。
- [FileIO 作者的說明](https://www.hiveworkshop.com/threads/fileio.307568/)指出 1.30 起不再要求開啟「Allow Local Files」。本次不修改登錄或用戶端設定。實際遊戲版本的權限、路徑、長字串與快取行為仍待驗證。

## 修正：地圖無法載入（2026-10-26）

### 現象

I4 完成後，測試地圖停在 WC3 主畫面，無法進入遊戲。

### 調查

以只還原一項修改的實驗地圖逐一測試（使用者在遊戲中執行）：

| 版本 | 內容 | 結果 |
|---|---|---|
| V0 | 原始地圖 | 可以進入 |
| V1 | 根目錄 `war3map.wts` 加回 UTF-8 BOM | 不行 |
| V2 | 還原 `war3map.w3i` 與 `config` 的 `SetMapName` | 可以進入 |
| V3 | 移除 `_Locales` 字串檔 | 不行 |
| V2a | 只還原 `war3map.w3i` | 可以進入 |
| V2b | 只還原 `SetMapName` | 不行 |

結論：`war3map.w3i` 的改寫造成問題。

### 原因

- 第 39 版的 `war3map.w3i` 在「載入畫面編號」之後，多一個 4 位元組整數（原始地圖的值為 64）。
- `mapTextSlots` 沒有跳過此整數，把它的第一個位元組（`0x40`，`@`）當作載入畫面模型路徑，之後的「載入畫面文字」位置也因此錯誤。
- 建置把 `TRIGSTR` 字串寫進此整數，檔案結構損壞，WC3 拒絕載入地圖。
- 既有測試用同一個解析器比較改寫前後的區段，所以無法發現位置錯誤。

### 修正

- `scripts/i18n-locales.cjs`：第 39 版在載入畫面編號後多跳過 4 位元組。
- 新增霧設定檢查：讀完文字欄位後，檢查霧的樣式、起點、終點、密度是否合理。不合理時停止建置，不寫出損壞的地圖。
- 新增測試：不依賴解析器，以固定位移檢查原始檔案（第 141 位元組的整數為 64、載入畫面文字位於第 146 位元組、霧設定為 3000、5000、0.5），並確認改寫後霧設定不變、位置錯誤時停止。
- 驗證：`pnpm run test:unit` 358 項通過；`pnpm run build` 成功。使用者確認修正後可以進入遊戲。
