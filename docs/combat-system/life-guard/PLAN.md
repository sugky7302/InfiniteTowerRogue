# 原生生命防護

## 問題

戰鬥系統的生命只存在 `CombatLife`。原生血條只顯示此值，最低保留 1。失能時使用無敵、移除目標分類與 `PauseUnit`。

無敵不能阻止全部原生扣血。以下來源可以使 1 點生命的單位死亡，或使血條與內部生命不同：

1. 原生技能傷害。目前只把普通攻擊的原生傷害設為 0。單位未失能時，原生技能傷害仍會減少原生生命。
2. 原生生命恢復。負數恢復不經過傷害事件，無敵也不能阻止。正數恢復使血條高於內部生命。
3. 其他程式直接寫入原生生命（`SetWidgetLife`、`SetUnitState`）。

## 決策

1. 已登錄目標的全部原生傷害都設為 0。只有普通攻擊進入本系統的檢定與結算。其他原生傷害來源由技能或戰鬥系統自己結算。
2. 登錄時把原生基礎生命恢復設為 0。生命恢復由本系統負責。
3. 戰鬥步進每 50 毫秒比對原生生命與應顯示值。差距大於 0.5 時，重新寫入顯示值。
4. 失能仍使用無敵、移除目標分類與 `PauseUnit`。無敵只用於阻止原生選取與原生傷害，不作為生命防護。
5. 規則：其他程式不得直接寫入已登錄單位的原生生命，也不得對其使用 `KillUnit`。生命變更必須透過 `CombatRegistry`。

## 限制

- 第 3 點不能阻止同一瞬間把生命設為 0 的寫入。第 5 點的規則處理此情況。
- 世界時鐘暫停時，戰鬥步進停止，所以比對也停止。基礎恢復已為 0。技能或物品給予的負數恢復可能在暫停中減少原生生命。目前沒有此類來源。之後加入時須再處理。

## 步驟

1. shared：`UnitActionNatives` 加入 `life`（讀取原生生命）與 `disableLifeRegen`（基礎恢復設為 0）。
2. features/combat：登錄時呼叫 `disableLifeRegen`。新增 `CombatRegistry.syncLife`。`CombatRuntime` 每次步進先呼叫它。傷害前事件對已登錄目標一律設為 0。
3. 測試：外部改寫原生生命後，步進會修正；非攻擊原生傷害被設為 0。
4. 工具驗證與遊戲內驗證。
