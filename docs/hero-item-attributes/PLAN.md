# 英雄與物品屬性系統（首版）

## 目的

- 英雄有自己的屬性狀態：一級屬性、職業等級與戰鬥等級。升級後重算二級屬性。
- 裝備提供固定屬性與隨機詞綴。穿上或卸下裝備後重算英雄數值，並接入戰鬥系統的傷害結算。

## 已決策（2026-11-04）

| 問題 | 決定 |
|---|---|
| 英雄範圍 | 預建配置＋職業升級。不做創角（自由配點、種族適性、幸運擲骰）與天賦 |
| 物品範圍 | 四個穿戴位置、固定屬性、普通階 1 項隨機詞綴 |
| 介面 | 只做純邏輯與數值接線。範例以聊天指令操作。自製介面另開設計稿 |
| 存檔 | 本版不接。只確定資料格式，存檔碼新版本另開階段 |
| 最大生命公式 | （基礎值＋加值）×（1＋百分比加總）＋固定值。裝備的「最大生命（固定）」屬於加值 |

## 範圍

### 包含

1. **英雄狀態**：一級屬性（力量、精準、身法、體質、精神、智力、幸運）、已認證職業與職業等級、戰鬥等級。親和保留欄位，本版沒有親和天賦，所以不作用。
2. **職業升級**：選擇一項已認證、未達最高等級的職業提高 1 級，套用該職業的每級固定成長，重算戰鬥等級。一階職業最高 5 級。
3. **物品基底**：名稱、裝備大類與子類標籤、穿戴位置、手數、固定屬性、詞綴池、必要使用知識。
4. **詞綴**：共用詞綴表（名稱、數值型態、數值表、作用參數、相容標籤、疊加群組）。鍛成時依階級抽取不重複的詞綴。本版只產生普通階。
5. **穿戴**：四個位置。檢查位置、手數與使用知識。穿上與卸下後重算數值。
6. **數值匯總**：英雄一級屬性＋全部穿戴物的固定屬性與詞綴 → 二級屬性與傷害修正。接入 `CombatStats`。
7. **比較**：同一位置，目前穿戴物與候選物的數值差異（`裝備體驗.md` 第一層）。只用文字輸出。

### 不包含

- 創角、種族、天賦、親和天賦。
- 精良以上階級的產生、升階、有限重鑄、鍛造值、材料與鍛造。共用表仍保存四階區間，供之後使用。
- 魔導武裝（刻印容量、鑲嵌、陣列、共振、調諧、裝備充能）。
- 背包（12 格、堆疊、攜行減速）。屬於活動系統。範例只用簡單的持有清單。
- 經驗值來源。範例以指令升級。
- 自製介面、存檔碼、物品掉落。
- 知識的形成與學習。英雄的已知知識是預建清單。

## 設計

### 1. 模組位置

| 位置 | 內容 |
|---|---|
| `src/entities/character/` | 英雄狀態、職業資料（每級成長、最高等級）、升級規則。既有 `scholar`、`patrolMachine` 保留 |
| `src/entities/item/`（新） | 物品基底資料、詞綴表、詞綴抽取、穿戴位置規則。輸出本模組自己的屬性加成型別 |
| `src/features/equipment/`（新） | 穿戴狀態（裝備配置）、穿脫檢查、匯總英雄與裝備的數值、比較 |
| `src/app/` | 範例：聊天指令；把匯總結果接到 `CombatStats` |

- `entities/item` 不得 import `entities/combat` 或 `entities/character`（同層規則）。它輸出中性的屬性加成清單。`features/equipment` 把清單轉成 `CombatBonuses` 與傷害修正。
- 英雄狀態不保存穿戴物。穿戴狀態放在 `features/equipment`。

### 2. 英雄狀態

```ts
interface HeroState {
    readonly attributes: PrimaryAttributeSet; // 七項一級屬性＋親和
    readonly classes: readonly ClassLevel[];  // { classId, level }，依認證順序
    readonly knowledge: readonly string[];    // 已形成的知識名稱（預建）
}
```

- 戰鬥等級＝全部職業等級的和。不另存。
- 升級：`levelUp(hero, classId)` 傳回新狀態或失敗原因（未認證、已達最高等級）。不修改原物件。
- 職業資料：`{ id, tier, growth }`。最高等級＝階級 × 5。本版只登錄符文學徒（一階，每級智力 +1）。
- 預建符文學者：一級屬性沿用 `scholar`（2、4、4、0、9、16、0）；符文學徒 1 級；已知知識為技能需要的知識，以及「魔法解析」。
- 目前技能系統在建置時讀取 `scholar` 常數（例如法力容量）。本版不改此行為。英雄升級後的智力變化只作用於戰鬥數值；技能資源的接線屬於後續階段，並在已知限制列出。

### 3. 物品階級與詞綴

- 物品階級：`ItemTier` 常數物件（普通、精良、名品、傳世）。隨機詞綴數量為 1、2、3、4。
- 詞綴表的資料直接取自 `詞綴.md`：比例與百分點表（微幅、標準、強效 × 四階），以及固定值表。
- 本版詞綴池只放已能作用到戰鬥系統的詞綴：

| 詞綴 | 數值型態 | 數值表 | 接到 |
|---|---|---|---|
| 物理傷害、火焰傷害、冰霜傷害 | 百分比 | 標準 | 傷害結算的傷害增加（同群組相加） |
| 暴擊率（近戰、法術） | 百分點 | 標準 | 分類暴擊率的其他加成 |
| 攻擊速度 | 百分比 | 標準 | 攻擊速度的其他加成 |
| 單一元素抗性（火焰、冰霜） | 百分點 | 標準 | 元素抗性 |
| 受到直接傷害降低 | 百分比 | 微幅 | 承傷降低 |
| 最大生命（百分比） | 百分比 | 標準 | 最大生命的百分比（同群組相加後乘算） |
| 最大生命（固定） | 固定值 | 專用表 | 最大生命的加值（在百分比之前） |
| 近戰攻擊力（固定）、法術強度（固定） | 固定值 | 專用表 | 對應二級屬性的其他加成 |
| 迴避（固定） | 固定值 | 專用表 | 迴避的裝備加成 |
| 護甲防禦（固定）、裝備防護（固定） | 固定值 | 專用表 | 物理防禦、法術防禦 |
| 固定護甲穿透、固定法術防禦穿透 | 固定值 | 專用表 | 傷害結算的固定穿透 |

- 不放入本版：施法速度、移動速度、裝備充能恢復、元素充能恢復、護盾效率、控制持續時間縮短、條件傷害、條件恢復效率。
- 抽取：
  - 依物品基底的詞綴池與權重抽出不重複的詞綴，數量依階級。
  - 每項詞綴在目前階級區間內，等機率抽一個整數值（`詞綴.md`：只保存整數時，所有可用整數等機率）。
  - 亂數由呼叫者傳入（WC3 中使用同步的 `GetRandomInt`）。純規則不讀取 WC3。
- 保存：`{ affixId, value }`。百分位由值與區間計算，只用於顯示與之後的升階。
- 物品實例：`{ id, baseId, tier, affixes }`。`id` 是範例內唯一的整數。

### 4. 穿戴位置與檢查

- 位置：`EquipSlot` 常數物件（主武器、副手、防具、工具）。
- 穿上前依序檢查。任一項失敗時不改變狀態，並傳回全部失敗原因：
  1. 物品基底的位置與目標位置相同。
  2. 雙手武器占用主武器與副手。穿上時副手必須是空的；否則失敗，不自動卸下（`裝備體驗.md`：不替玩家改動未指定的裝備）。
  3. 英雄已形成物品基底的必要使用知識。
  4. 同一物品實例不能同時在兩個位置。
- 卸下：位置變空，物品回到持有清單。

### 5. 數值匯總

> 英雄數值＝`deriveCombatStats`（英雄一級屬性與戰鬥等級，全部穿戴物的固定屬性與詞綴加總）

- 固定值詞綴與固定屬性加入對應二級屬性的「其他加成」。
- 最大生命：（40＋體質×5＋戰鬥等級×2＋加值）×（1＋百分比加總）＋固定值。裝備的固定詞綴與固定屬性是加值；「固定值」保留給之後的其他來源（本版為 0）。
- 傷害百分比、抗性、承傷降低、穿透轉成傷害結算的修正清單（`DamageStat`）。同名加成依 `效果互動矩陣.md` 相加。
- 主武器的武器資料（基礎傷害、係數）取代 `scholar.weapon`，供普通攻擊使用。
- 匯總是純函式。輸入相同時結果相同。全部數值在 32 位元範圍內，使用 `entities/combat` 的運算函式。

### 6. 試玩物品（試玩值）

| 基底 | 位置 | 標籤 | 固定屬性 | 必要知識 | 詞綴池 |
|---|---|---|---|---|---|
| 符文杖 | 主武器 | 武器、近戰武器、施法媒介 | 單手；4 ＋ 近戰攻擊力 × 0.5 | 無 | 法術強度（固定）、近戰攻擊力（固定）、火焰傷害、冰霜傷害、暴擊率（法術）、攻擊速度 |
| 訓練短劍 | 主武器 | 武器、近戰武器 | 單手；4 ＋ 近戰攻擊力 × 0.5 | 無 | 近戰攻擊力（固定）、物理傷害、暴擊率（近戰）、攻擊速度、固定護甲穿透 |
| 巡檢長槌 | 主武器 | 武器、近戰武器 | 雙手；6 ＋ 近戰攻擊力 × 0.75 | 無 | 近戰攻擊力（固定）、物理傷害、暴擊率（近戰）、固定護甲穿透 |
| 術式手冊 | 副手 | 施法媒介 | 無 | 魔法解析 | 法術強度（固定）、固定法術防禦穿透、火焰傷害、冰霜傷害 |
| 學徒長袍 | 防具 | 護甲、輕甲 | 裝備防護 ＋4 | 無 | 最大生命（固定）、最大生命（百分比）、迴避（固定）、裝備防護（固定）、火焰抗性、冰霜抗性、受到直接傷害降低 |

- 工具位置本版沒有物品。工具不在詞綴的相容標籤中，工具規則屬於活動系統。
- 全部值都需要試玩調整。

### 7. 範例指令（app）

| 指令 | 作用 |
|---|---|
| `-hero` | 顯示英雄的一級屬性、職業等級、戰鬥等級與主要二級屬性 |
| `-hero-up` | 符文學徒升 1 級。已達 5 級時顯示原因 |
| `-item-new <基底>` | 產生一件普通階物品，放入持有清單（範例上限 12 件） |
| `-items` | 列出持有清單與穿戴物：編號、名稱、階級、固定屬性、詞綴 |
| `-equip <編號>` | 穿上。顯示與目前同位置物品的差異；失敗時顯示全部原因 |
| `-unequip <位置>` | 卸下 |

- 數值改變時，WC3 英雄的最大生命跟著更新（只用於顯示）。
- 最大生命改變時的目前生命（2026-11-04 決定）：增加時，目前生命增加相同的值；減少時，目前生命不超過新上限。失能中的英雄維持 0。
- 沒有主武器時，普通攻擊停用，顯示「沒有武器」。規則沒有徒手傷害資料（`武器與戰鬥資源.md`：沒有致傷資料不能造成傷害）。
- 範例開始時，英雄穿著一件新產生的符文杖與學徒長袍，持有清單為空。
- 聊天輸入只作為範例。遊戲邏輯不得比較翻譯後的文字；物品基底以 ID 對應。

## 已知限制

- 技能系統的法力容量與恢復在建置時讀取 `scholar` 常數。升級後的智力不改變法力。
- 英雄與裝備不在存檔碼中。重新開始遊戲後回到預建狀態。
- 範例的持有清單不是背包規則。
