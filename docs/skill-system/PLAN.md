# 技能系統（首版：符文學者）

## 目的

- 實作《沉冠遠征》首版配置「符文學者」的兩個技能：火球術與寒冰箭。
- 建立可擴充的施法流程：開始 → 施法 → 投射 → 命中 → 結算。之後的技能使用同一流程。
- 規則來源：`docs/dnd/`。遊戲層級的取捨：`docs/rogue/`。

## 已決策（2026-11-03）

| 問題 | 決策 |
|---|---|
| 首版範圍 | 見「範圍」。構築方案只讀取技能複雜度；傷害只做部分結算；不做精通技法、迴路負載、知識形成。 |
| D20 檢定時機 | 施法完成時擲骰。失敗時技能失效並顯示；成功時才產生投射物，碰撞即命中。 |
| 單位換算 | 1 碼 = 32 WC3 單位。 |
| 文件缺少的數值 | Claude 先填入試玩值，標記為「試玩值」。 |
| 角色數值 | 首版使用固定數值，不做屬性系統。 |
| 寒冰箭施法時間 | 依公式計算，不使用文件開頭的 1.5 秒。 |
| 冷卻與法力的權威狀態 | 使用 WC3 原生的冷卻與法力。引擎負責阻止施法、圖示變灰與提示。另做「暫停轉接」處理戰術暫停。 |

## 範圍

### 包含

1. 施法流程：開始條件（法力、冷卻）、施法時間、施法中斷、D20 技能檢定、投射物、命中、結算。
2. 技能：火球術、寒冰箭。
3. 資源：法力、冷卻（使用 WC3 原生機制，加上暫停轉接）。
4. 傷害（部分）：法術基礎傷害、法術強度係數、有效法術防禦、防禦減傷、傷害抗性、護盾。
5. 持續效果：燃燒（週期傷害）、移動減速（狀態）。
6. 固定步進的幀來源（新增至 RxWC3），供投射物使用。
7. 範例地圖：符文學者英雄與測試敵人。

### 不包含

- 構築方案的規則、精通技法、迴路負載、知識形成。
- 傷害的附加與轉換、暴擊、格擋、壓碎、穿透、承傷降低、固定減傷、吸收、易傷、分攤、斬殺、生命偷取、反射。
- 屬性系統、裝備、天賦。
- 戰術暫停的單位暫停部分（屬於戰鬥系統）。見「已知限制」。

## 規則摘要（來自 `docs/dnd/`）

| 規則 | 內容 | 來源 |
|---|---|---|
| 施法時間 | 原始 = 0.5 秒 + 技能複雜度 × 0.25 秒 + 性能附加時間；實際 = 原始 ÷（1 + 施法速度），最低 0.1 秒 | `規則/時間與距離.md` |
| 射程級距 | 有效射程 = 基準射程 × 2^級距。每提高一級，須選一種支付方式（本稿選擇：施法時間 +0.25 秒） | `規則/時間與距離.md` |
| 命中時間 | 施法開始 + 實際施法時間 + 觸發延遲 + 飛行距離 ÷ 投射速度 | `規則/時間與距離.md` |
| 技能檢定 | 擲出 D20，骰值必須大於檢定值。檢定值 = 9 + 挑戰等級 + 技能複雜度 + 不利修正 − 戰鬥等級 − 屬性修正值 − 知識修正值 − 有利加成，範圍 2～19 | `規則/檢定值.md`、`規則/D20檢定.md` |
| 攻擊與迴避 | 攻擊檢定把目標的迴避加入不利修正。迴避 = 身法修正值 | `規則/檢定值.md`、`屬性/二級/迴避.md` |
| 屬性修正值 | min(10, ⌊√一級屬性⌋) | `屬性/二級/屬性修正值.md` |
| 法術強度 | 智力 × 2 + 精神 | `屬性/二級/法術強度.md` |
| 法術傷害 | 技能基礎值 + 法術強度 × 技能係數 | `規則/傷害.md` |
| 法術防禦 | 基礎法防 = 精神 × 2 + 體質；減傷率 = min(80%, 法防 ÷ (法防 + 100)) | `規則/傷害.md` |
| 傷害抗性 | 抗性後傷害 = 防禦後傷害 × (1 − 最終抗性)；最終抗性範圍 −100%～75% | `規則/傷害.md` |
| 護盾 | 護盾後傷害 = max(0, 傷害 − 護盾容量)。護盾吸收不算生命損失 | `規則/傷害.md` |
| 法力 | 容量 = 10 + 精神 × 3 + 智力 × 2。開始施法時扣除；施法中斷不返還；不足時不能開始 | `戰鬥資源/法力.md`、`規則/資源.md` |
| 冷卻 | 技能成功開始後進入冷卻 | `規則/資源.md` |
| 週期效果 | 第 n 次觸發時間 = 開始 + 首次延遲 + (n − 1) × 週期。同來源再次施加時刷新剩餘時間，不疊層 | `規則/持續與週期.md` |
| 移動減速 | 降低移動速度，仍可移動 | `規則/狀態與解除.md` |

## 設計

### 1. 模組位置

| 位置 | 內容 |
|---|---|
| `src/shared/rxwc3/` | 新增固定步進的幀來源（通用功能） |
| `src/feature/skill/` | 技能定義、施法流程、投射物、檢定 |
| `src/feature/combat/` | 傷害結算（部分）、持續效果（燃燒、減速）、冷卻與法力的暫停轉接 |
| `src/shared/wc3-def/` | 新增的原生函式介面與 WC3 實作 |

純規則（公式、檢定、傷害、持續效果的時間計算）不得使用 WC3 原生函式，必須能在 Node 中測試。

### 2. 施法流程

```
玩家下令施法（WC3 Channel 型技能）
  → 引擎檢查法力與冷卻。不足時引擎阻止施法並提示，本系統不介入。
  → 引擎扣除法力並開始冷卻（引導技能在開始時扣除，中斷不返還，符合規則）。
  → onSpellChannel：本系統開始追蹤此次施法。
  → 世界時鐘計時「實際施法時間」。期間施法者收到任何新命令（移動、停止、其他技能）或引導結束時，取消此次施法並顯示「中斷」。
  → 計時完成：本系統對施法者下達停止命令，結束 WC3 的引導。
  → D20 技能檢定：失敗時顯示「失敗」，流程結束。
  → 產生投射物，由幀來源更新位置。
  → 命中：結算傷害與持續效果。
```

- WC3 技能使用 Channel 型基底。**施法時間由本系統以世界時鐘控制**（S3 修正，2026-11-03）：
  - WC3 的引導時間設定為很長的值（試玩值 60 秒），只用於顯示施法動作，不決定施法完成。
  - 中斷偵測：監聽施法期間施法者收到的命令（玩家單位命令事件）。不只依賴 WC3 的施法結束事件。
  - 本系統在計時完成後下達的停止命令，不得被視為中斷。
  - 原因：世界時鐘暫停時，WC3 的引導照常前進並結束，導致施法被取消（S3 問題 4）；且單位曾不理會移動與停止命令（S3 問題 1）。
- 計時使用世界時鐘與 `Phase.Combat`。
- D20 使用同步的隨機數（`GetRandomInt`），經原生函式介面注入。Node 測試注入固定數列。
- 法力消耗與冷卻寫入 WC3 物件資料（建置時由技能定義產生）。需要在執行時調整時，使用 `BlzSetUnitAbilityCooldown`。
- 符文學者的法力上限與恢復速度，在建立英雄時以 `BlzSetUnitMaxMana`（或對應的原生函式）與 `BlzSetUnitRealField` 設定為固定數值。

### 2a. 暫停轉接（冷卻與法力）

WC3 的冷卻與法力恢復跟隨遊戲時間，不受世界時鐘控制。暫停轉接訂閱世界時鐘的暫停與恢復：

| 世界時鐘 | 冷卻 | 法力恢復 |
|---|---|---|
| 暫停 | 讀取每個追蹤中技能的剩餘冷卻（`BlzGetUnitAbilityCooldownRemaining`）並保存；結束冷卻，並停用技能（`BlzUnitDisableAbility`，停用但不隱藏，圖示變灰） | 保存恢復速度，設為 0 |
| 恢復 | 重新啟用技能，再以保存的剩餘時間開始冷卻（`BlzStartUnitAbilityCooldown`） | 還原恢復速度 |

- S3 修正（2026-11-03）：原做法「每 1/32 秒重設剩餘時間」會使冷卻圖示一直閃動，已改為上表的停用做法。停用的圖示也可以讓玩家知道目前是暫停狀態。
- 暫停期間不得施法。阻止施法屬於戰鬥系統的戰術暫停；首版只確保冷卻與法力的數值不變。
- 原生函式經由原生函式介面注入，Node 可以用假的實作測試轉接邏輯。
- 須在遊戲中驗證：`BlzStartUnitAbilityCooldown` 能精確設定剩餘時間；冷卻圖示顯示正確。

### 3. 投射物與幀來源

- 在 RxWC3 新增固定步進的幀來源（例如 `frames()`）：使用一個週期性 WC3 計時器，以固定間隔（試玩值 1/32 秒）送出值，並受世界時鐘的暫停控制。
- 全部投射物共用同一個幀來源，不為每個投射物建立 `interval`。
- 寒冰箭追蹤目標單位；目標死亡或消失時，投射物失效。火球術飛向落點，抵達後展開區域。
- 投射物的外觀使用特效模型，不使用單位。

### 4. 傷害結算（部分）

依 `規則/傷害.md` 的順序，只實作下列步驟：

1. 法術基礎傷害 = 技能基礎值 + 法術強度 × 技能係數。
2. 有效法術防禦與防禦減傷。
3. 傷害抗性。
4. 護盾。
5. 剩餘值扣除生命。

- 直接傷害與燃燒的每次週期傷害，是不同的傷害事件。
- 結算結果透過 WC3 傷害事件套用，並避免 WC3 自身的護甲與攻擊類型再次修改數值。做法由實作者決定並記錄。
- 數值精度：WC3 浮點數為 32 位元（見 `AGENTS.md`）。顯示數值時處理負零。

### 5. 持續效果

- 燃燒：週期事件依「持續與週期」公式排程。同來源再次施加時刷新剩餘時間。可燃條件以試玩規則判定（測試敵人可燃）。
- 移動減速：倍率 × 0.5，8 秒，寒冰箭減速群組。同群組再次施加時刷新；數值較強者生效。
  - S3 修正（2026-11-03）：WC3 的遊戲常數「單位移動速度下限」預設為 150，使 270 × 0.5 = 135 變成 150。在地圖的遊戲常數中降低此下限。可設定的最小值須在遊戲中確認。
- 持續效果的計時使用世界時鐘。

### 6. 效能（依 `docs/rxwc3/benchmark/PLAN.md` 的使用建議）

- 高頻事件使用 Observable。
- 不要頻繁寫入依賴者很多的 signal。法力可以是 signal，但只讓少量介面元素依賴它。
- 投射物使用共用的幀來源。

## 待觀察：離開遊戲變慢（2026-11-03）

- 使用者觀察：遊戲開得較久時，離開遊戲需要較長時間。
- 量測方法：從外部讀取 WC3 程序的記憶體，並量測正常關閉視窗所需的時間。

| 情境 | 執行時間 | 記憶體 | 關閉時間 |
|---|---:|---:|---:|
| 技能範例，閒置（第一次） | 約 160 秒 | 約 2.85 GB，持平 | 33.9 秒 |
| 技能範例，閒置（重測 3 次） | 50 秒至 3 分鐘 | 約 2.8 至 2.9 GB，持平 | 2.1 至 4.1 秒 |

| 技能範例，持續施法 | 約 3.5 分鐘 | 約 2.9 GB，持平 | 2.0 秒 |

## 已知限制

- 施法流程停止運作時（例如程式錯誤使訂閱結束），WC3 引導會持續到 60 秒才結束，技能看起來卡在施法狀態。

- 戰術暫停：世界時鐘暫停時，本系統的計時（施法、冷卻、持續效果、投射物）會停止。但 WC3 單位的動作（移動、攻擊）不受世界時鐘控制。`PauseUnit` 會打斷引導施法（`docs/rxwc3/m5/PLAN.md`）。完整的戰術暫停由戰鬥系統處理。
- 文件缺少的數值都是試玩值，需要試玩後調整。
