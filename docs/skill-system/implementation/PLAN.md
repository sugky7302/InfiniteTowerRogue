# S0 至 S2 實作記錄

本稿的完成狀態只表示 S0 至 S2 的程式與工具驗證完成。唯一規格為 `../PLAN.md`，主規格保持 `false`。未執行 S3、遊戲啟動或 Git 提交。

## S0：固定步進幀來源

- `frames()` 從 RxWC3 入口匯出。預設呼叫取得相同的共用來源。
- 每個來源使用一個週期性原生計時器，預設間隔為 `1 / 32` 秒。第一位訂閱者啟動計時器，最後一位取消時停止並銷毀計時器。重新訂閱會重新建立計時器。
- 幀資料只有 `deltaSeconds`。它表示固定步長，不是累計世界時間。暫停期間略過幀，恢復後不補發。沒有浮點時間累加或無上限幀編號。
- `FrameNatives.start` 注入原生計時器。Node 使用假的計時器。正式實作在 `wc3-def/wc3-frame-natives.ts`。
- 所有投射物共用一個幀訂閱。每幀回呼與區域回呼在初始化時建立，不在每幀建立閉包。
- `Clock.pauseChanges` 是新增的 Observable。只有首次暫停及最後一次恢復時通知。既有排程 API 的計時與順序不變。

## S1：純規則

- `feature/skill/definitions.ts` 集中技能及角色數值，標示試玩值來源。
- 施法時間含射程級距。火球術為 1.5 秒，寒冰箭為 1.75 秒。
- 技能檢定限制為 2 至 19。骰值必須嚴格大於門檻。火球術門檻為 5，寒冰箭為 7。
- 法術強度為 41，法力容量為 69。寒冰箭基礎傷害為 42.8，測試敵人法防後約為 38.2143。
- 傷害順序為基礎值與係數、防禦、抗性、護盾、生命損失。未加入規格排除的結算項目。
- 燃燒使用絕對整數毫秒排程，含結束端點。同來源刷新只取消未發生事件，再從刷新時刻排程。已發生傷害不追回。`clear()` 可提前解除。
- 減速按來源與群組保存。同來源及群組刷新；全部有效條目中以較強者生效，不相乘。較強者到期後，較弱者仍可繼續作用。
- 平時法力與冷卻的權威仍是 WC3。快照只在暫停期間使用。

以下 S2 記錄保留首次實作狀態。施法、Channel 與暫停轉接的現行做法見「S3 修正」。

## S2：WC3 整合

### 物件與載入

| 代碼 | 內容 |
|---|---|
| `A0SF` | Channel 點目標火球術；F 鍵；引導 1.5 秒；法力 15；冷卻 4 秒 |
| `A0SI` | Channel 單位目標寒冰箭；I 鍵；引導 1.75 秒；法力 10；冷卻 0 秒 |
| `H0SS` | 符文學者英雄，直接持有兩個一般技能，無須學習 |
| `h0SE` | 測試敵人 |

`main.ts` 只替換基準範例的 import 與 hook。技能範例模組的 `compiletime` 回呼呼叫 `scripts/skill-objects.cjs`，並從技能定義讀取資料。轉換器先處理相依模組，再執行 `main.ts` 原有的 `objectData.save()`。因此，主程式的儲存動作也包含新物件。此做法與 i18n 範例相同。

套件把 Channel 目標與旗標宣告為字串。輸出時仍須寫入整數。套件也沒有保存技能等級與資料指標。建置輔助程式只修正兩個新技能：逐級欄位使用第 1 級，`Ncl1` 至 `Ncl6` 使用資料指標 1 至 6。Node 與最終 MPQ 驗證均檢查這些欄位。

Channel 基礎命令分別為 `flamestrike` 與 `frostnova`，避免共用命令。施法前搖與收招設為 0，引導時間使用公式結果。引擎負責法力、冷卻、目標限制與中斷。

### 流程與傷害

- `onSpellChannel` 接上既有 `whenCastCompleted`。完成排程使用世界時鐘及 `Phase.Combat`。新施法取代舊施法，施法結束取消未完成排程。
- 完成時透過原生介面呼叫同步的 `GetRandomInt(1, 20)`。失敗只顯示結果，成功才建立特效投射物。
- 寒冰箭追蹤目標；目標死亡或移除後清理特效。火球飛向固定落點，再列舉半徑 96 內全部單位，不排除友軍或施法者。
- 群組及傷害觸發器都在共同啟動流程預先建立。區域命中不建立新群組，投射物不使用單位作為外觀。
- 直接傷害與每次燃燒分別呼叫 `UnitDamageTarget`，使用 `ATTACK_TYPE_NORMAL`、`DAMAGE_TYPE_UNIVERSAL`，且 `attack` 為 false。
- 預建的 `EVENT_PLAYER_UNIT_DAMAGED` 觸發器在原生防禦計算後、扣血前呼叫 `BlzSetEventDamage`，固定為規則結算的生命損失。同步堆疊只標記本介面送出的來源、目標與數值，每筆事件只修正一次，不改寫一般攻擊。
- 原生傷害呼叫使用 `protectedCall`。失敗時先移除堆疊標記，再交給訂閱錯誤處理及 logger。
- 護盾吸收在原生傷害前完成。完全吸收時生命損失為 0，仍可施加減速。WC3 可能不送出零傷害事件，S3 不以該事件的存在作為通過條件。
- 浮動文字顯示成功或失敗、骰值、門檻、傷害、燃燒與減速。傷害顯示至小數一位，負零顯示為 `0`。

### 暫停轉接

轉接訂閱 `worldClock.pauseChanges`。第一次暫停時保存英雄法力、恢復欄位及各技能剩餘冷卻，並將恢復欄位設為 0。另一個不受世界時鐘控制的週期性計時器，每 `1 / 32` 秒重設保存的法力與冷卻。該計時器只在暫停期間存在。

最後一次恢復時，先停止轉接計時器，再還原法力、恢復欄位及剩餘冷卻。取消範例也先還原資源，再移除單位。多次暫停不覆寫第一次快照。

這是規格允許的「每幀重設剩餘時間」方案。兩次重設之間，圖示可能出現最多約一個步長的變化。實際設定精度、恢復欄位對英雄智力加成的作用及圖示是否閃動，都須由 S3 確認。

首版沒有暫停單位，也沒有使用 `PauseUnit`。暫停期間不要下達新施法命令。完整行為封鎖屬於戰鬥系統。原生 Channel 可能在世界暫停時自行結束，並取消未完成施法；這是主規格的已知限制。

## 補充試玩設定與差異

- 英雄體質缺值取 0，法防為精神 9 × 2 = 18，且在範例中可燃。未登記單位採用法防、抗性、護盾 0，且不燃燒。測試敵人使用規格固定值。
- 範例額外設定英雄基礎生命 1000、敵人生命 2000、原生護甲 20、移速 270。這些值供觀察使用。原生護甲刻意不設為 0，以確認沒有重複減傷。敵人停用普通攻擊，英雄停止獲取經驗。
- 新增 `-skill-status` 顯示世界時間、法力、恢復欄位、火球冷卻、敵人生命及移速；`-skill-move` 讓敵人在兩端移動；`-skill-stop` 清理範例。
- 建置流程更新 `i18n/objects/` 三個字典。沒有英文與簡體翻譯的新物件沿用正體文字，既有翻譯鍵保留。
- 沒有變更技能數值或排除項目。沒有實作 S3。

### 施法、中斷與命令順序

- `SkillRuntime.track` 改用世界時鐘排程，階段為 `Phase.Combat`。火球術仍為 1.5 秒，寒冰箭仍為 1.75 秒。Channel 引導改為 60 秒，只維持施法動作。
- 新增 `onUnitOrder`，支援全域訂閱及 `.of(unit)`。沿用 `UnitSource` 與既有事件中樞。第一次訂閱才建立觸發器，跨路由依訂閱順序分發。原生註冊與快照位於 `wc3-def`。
- 註冊無目標、點目標、物件目標三種玩家單位命令事件。快照保存單位、命令編號、命令種類、目標 widget 與點座標。單位目標與物件目標是同一事件，兩者都為事件 40，只註冊一次。依據為遊戲 `common.j` 的常數宣告。[common.j](https://github.com/Warcraft-III-Community-Edition/W3CE/blob/main/Scripts/common.j)
- 起始順序採用「下令施法 → 命令事件 → 進入射程 → SPELL_CHANNEL → SPELL_CAST → SPELL_EFFECT」。命令事件在下令時發生，施法事件在開始施法後發生。此判斷依據施法事件的實測討論，仍須目前遊戲版本複驗。追蹤狀態在 CHANNEL 才建立，因此起始命令不會取消新施法。程式沒有忽略相同命令編號，也沒有略過第一個後續命令。重施相同技能也會中斷舊施法。[實測討論](https://www.hiveworkshop.com/threads/generic-buff-recognition.354595/)
- 完成順序為「清除施法狀態與排程 → 下達停止 → 收到同步命令與引導結束 → D20 檢定」。Node 與 Lua 都以假的原生停止函式同步送出兩種事件，確認只結算一次。
- 施法期間收到任何新命令即取消排程，無須等待引導結束。保留同技能的引導結束事件作為中斷條件。取消時顯示一次「中斷」。後續命令或結束事件不會重複顯示。
- 暫停時施法排程停止，恢復後使用剩餘世界時間完成。測試也涵蓋暫停期間收到命令或引導結束，以及戰鬥階段先於同時到期的預設階段。

## 尚未解決的問題

1. S3 複驗尚待使用者完成。命令與引導事件順序、停用時的引導動作、冷卻圖示及 135 移速，仍須目前遊戲版本的證據。
2. 60 秒引導是試玩值。若暫停延續至原生引導到期，仍會收到引導結束並顯示「中斷」。此值不保證無限期保留引導。
3. 移速下限 0 已寫入最終 MPQ。引擎允許的最小值與實際移速尚待遊戲確認。
4. 法力恢復欄位設為 0，恢復時還原法力快照。英雄智力與該欄位的合成方式仍待確認。此次依新設計移除每幀資源重設。
5. 完整戰術暫停的單位移動、攻擊及多人行為仍待戰鬥系統與遊戲驗證。
