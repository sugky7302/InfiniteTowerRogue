# 知識面板

## 目的

知識體系取代天賦（物品欄設計稿的決策）。本設計加入一個獨立視窗，讓玩家查看英雄的知識：名稱、分類、等級與解析進度。

## 使用者決策（2026-11-05）

| 問題 | 決策 |
|---|---|
| 顯示內容 | 名稱、分類、等級、解析進度 |
| 版面 | 像物品欄一樣一格一格排列；全螢幕；可以捲動 |
| 功能 | 篩選與排序 |
| 位置 | 獨立視窗 |
| 操作 | 只能查看。研究與學習另立設計稿 |
| 每格內容 | 圖示與名稱。等級、經驗與其他資料放在說明框 |
| 顯示哪些知識 | 只顯示英雄接觸過的知識（經驗大於 0，包含解析中）。沒有接觸過的不顯示 |
| 經驗 | 上限 4000。經驗曲線與取得量之後可以調整，經驗可以有小數 |
| 說明框的經驗 | 本級進度／本級所需（審核後決定） |
| 說明框的形式 | 浮動 Tooltip，顯示在滑鼠所在格子的旁邊（審核後決定） |
| 不合法的輸入 | 等級與格式函式收到負數或非整數時丟出錯誤（審核後決定） |
| 捲動的遊戲內驗證 | 測試指令加入只用於顯示的假知識（審核後決定） |
| `-know-exp` 的編號 | 從 0 開始，等於目錄編號與存檔位置（審核後決定） |
| 滿版的範圍 | 整個螢幕，包含寬螢幕的兩側 |
| 內建面板 | 遊戲開始就永久隱藏（`hideOrigin`）。之後自製全部介面。隱藏與替代介面另立設計稿，見「不包含」 |

## 規則來源

`docs/dnd/規則/知識體系.md`：

- 經驗未達第一個門檻時稱為「解析進度」，尚未形成知識。達到門檻後為 1 級。
- 升至目標等級所需經驗＝100×目標等級。超出的經驗保留。所以累積經驗與等級的關係：
  - 1 級需要累積 100，2 級需要 300，3 級需要 600，n 級需要 50×n×(n+1)。
  - 上限 4000 時最高 8 級（累積 3600）。
- 這是暫定公式。曲線放在 `config/`，之後可以調整，不改其他程式。
- 每項知識有固定的主要節點類型（核心、型態、效果、修飾、觸發、橋接）、主要歸屬法則（七大法則之一）與知識深度（基礎、專業、高等、統合）。
- 規則文件寫「沒有等級上限」。經驗上限 4000 是**本版本的限制**，不是規則的改變。
- 已發布存檔版本的欄位寬度、範圍與經驗單位固定不變。之後提高上限或改變單位時，新增存檔版本與轉換規則，並重新計算打包與存檔碼的上限。
- 曲線改變時，已保存的累積經驗不變，等級依新曲線重新計算。

## 現況

- `Hero.knowledge` 是知識名稱的清單（符文學者有 7 項）。沒有等級與經驗。
- 存檔第 4 版。`hero` 區段的 `knowledge` 是 32 個 0／1 旗標，對應 `src/app/hero-save.ts` 的知識目錄。
- `SaveParticipant.previous` 只描述第 3 版轉第 4 版。
- `maxPackedBytes` 是 768。第 4 版最壞情況為 5677 位元（710 位元組）。
- `HeroExample` 的快照、讀檔、升級與 `-hero-forget` 只複製知識名稱。
- 物品欄框架在 `src/app/inventory-ui.ts`。`runInventoryUi` 只傳回停止函式，外部無法開關視窗。
- `FrameNatives` 沒有讀取框架事件數值（`BlzGetTriggerFrameValue`）的方法。
- 技能定義中的 `knowledge` 是檢定用的數字，與本設計無關。

## 做法

### 資料（entities）

新增 `src/entities/knowledge/`。它不 import `entities/character`，`character` 也不 import 它。

- `config/`：
  - 知識目錄。每項有編號、名稱、主要節點類型、主要歸屬法則、知識深度、一句說明。資料從 `docs/dnd/知識/` 的頁首與第一段手動整理。
  - 首版有 7 項，順序與編號等於 `heroKnowledge`。**已發布的編號不得改變或重新排列**，因為它是存檔位置。存檔保留 32 個位置。
  - 經驗單位、上限與曲線常數。
- `model/`：
  - 經驗單位：以 **0.1 經驗** 為一個整數單位（`350` 表示 35.0 經驗），顯示時才轉換。原因：WC3 Lua 的浮點數只有約 7 位有效數字，不得用浮點數累加（AGENTS.md）。上限 4000 經驗＝40000 單位。
  - 等級：`knowledgeLevel(units)`、門檻、最高等級、本級進度。只用整數運算，結果不得超過 2147483647。
  - 知識狀態：知識編號 → 累積經驗單位。0 表示沒有接觸過；大於 0 且未達 1 級門檻表示解析中；達到門檻表示已形成。

### 狀態的擁有者（app）

- `HeroExample` 持有每名英雄的知識狀態。這是經驗的**唯一來源**。
- `Hero.knowledge` 一律由知識狀態中已形成的項目產生（依目錄順序）。技能與裝備的知識檢查不變。
- 必須同步的流程：
  - 新英雄：英雄設定中的每項知識設為 1 級的門檻（`knowledgeLevelThreshold(1)`，目前為 1000 單位）。
  - 快照與讀檔：保存與還原完整知識狀態。
  - 升級：保留知識狀態。
  - `-hero-forget`：全部經驗設為 0。
- 知識減少時的裝備（第三輪審核發現，使用者決定，2026-11-05）：
  - 經驗降低使已形成的知識變回解析中或 0 時，已穿戴、但不再符合知識條件的裝備**自動卸下到背包**。原因：否則狀態無法存檔（編碼時會重新檢查穿戴條件）。
  - 背包的空格少於要卸下的件數時，整個變更失敗，知識與裝備都不變。
  - `-know-exp` 與 `-hero-forget` 都適用此規則。之後正式的遺忘機制沿用它。
  - `-know-exp`：改變知識狀態後，更新 `Hero.knowledge`、物品欄說明與知識視窗。

### 存檔

- 升為**第 5 版**。第 3 版與第 4 版的格式不變，已存在的存檔碼仍可讀取。
- 擴充 `features/save` 的版本機制，讓參與者可以描述多個舊版本，並依序轉換：第 3 版 → 第 4 版（裝備，沿用現有轉換）→ 第 5 版（知識）。
- 第 5 版 `hero` 區段的 `knowledge` 改為 32 個經驗單位，每項 0～40000（16 位元）。增加 480 位元。
- `maxPackedBytes` 由 768 改為 800。第 5 版最壞情況為 6157 位元（770 位元組），存檔碼最長約 1513 字元，低於 1600 字元的上限。
- 第 4 版轉第 5 版：旗標 1 轉為 1000 單位，0 轉為 0。這是第 4 版的固定語意，曲線改變時也不變。
- 讀檔時拒絕：
  - 經驗不是 0～40000 的整數。讀檔不得截斷到上限。
  - 目錄沒有定義的位置（目前 7～31）不是 0。
  - 沒有英雄時，任何經驗不是 0。
- 保留 HMAC 驗證。測試也要包含重新簽章後仍不合法的資料。

### 介面

新增 FSD 的 `widgets` 層（使用者決定，2026-11-05）。知識面板放在 `src/widgets/knowledge-panel/`：

- `model/`：篩選、排序、捲動的純函式與面板狀態。
- `config/`：版面尺寸、節點類型圖示、中文顯示名稱、排序用的固定順序。
- `ui/`：版面與說明框文字的純函式，以及框架的建立與事件（透過 `FrameNatives`，可在 Node 中以假實作測試）。
- `index.ts`：公開 API，例如 `runKnowledgePanel`。

依賴方向改為 app → widgets → features → entities → shared。面板只 import `@entities/knowledge` 與 `@shared/*`。開關、互斥與指令由 app 層組合。

需要的設定（已完成，2026-11-05，使用者同意）：

- `tsconfig.json` 與 `tsconfig.test.json` 加入路徑別名 `@widgets/*`。
- Steiger 認得 `widgets` 層（實測）。沒有被 import 的 slice 會產生 `fsd/insignificant-slice` 錯誤。
- `AGENTS.md` 的分層表、依賴方向、segment 規則與路徑別名加入 `widgets`。

物品欄是否搬到 `widgets/` 不在本設計範圍。

- 開關：
  - 物品欄按鈕旁加入「知識」按鈕。
  - 知識視窗與物品欄互斥：打開一個時關閉另一個。按鈕、`-bag` 與 `-know` 都遵守此規則。
  - 兩個視窗的執行函式都提供開關介面（打開、關閉、目前是否打開、打開時的通知）。互斥由 app 層組合；知識面板不 import 物品欄。
- 版面（整個螢幕）：
  - WC3 的框架座標以 4:3 區域為準（寬 0.8、高 0.6）。寬螢幕時，可見的寬度是 `0.6 × 螢幕寬 ÷ 螢幕高`，左右各超出 4:3 區域一半的差值。
  - 螢幕寬高只能由本地讀取（`BlzGetLocalClientWidth`、`BlzGetLocalClientHeight`），所以只用於本地的位置與大小，不得影響遊戲狀態。每次打開時重新計算，讓玩家改變視窗大小後仍然滿版。
  - 掛在 `ORIGIN_FRAME_GAME_UI` 的框架可能被限制在 4:3 區域內。面板需要掛在不受限制的父框架上，候選是 `ConsoleUIBackdrop`。這需要遊戲內實驗確認（K5 的實驗 E1）。
  - 面板必須在內建面板隱藏與不隱藏時都能正常顯示。
  - 上方：標題、篩選按鈕、排序按鈕、關閉按鈕。
  - 中間：格子區。每格有節點類型圖示與名稱。每列 6 格、顯示 5 列，共 30 格。
  - 右側：捲軸（上、下按鈕與目前位置）。
  - 說明框是浮動的 Tooltip，不佔用面板的固定區域。
- 框架：
  - 新增 `assets/ui/knowledge.fdf` 與唯一的樣板名稱，加入主 TOC（CRLF，最後一行之後有空行）。
  - 全部玩家共同建立相同框架，只用本地玩家切換可見性。
  - 格子只建立一次（30 格與其子框架）。捲動與篩選只改變內容與可見性。沒有內容的格子隱藏。原因：物品欄 I5 的經驗是反覆建立框架會讓關閉遊戲時卡住。
- 捲動：
  - 滑鼠滾輪與上、下按鈕每次移動一列。
  - `FrameNatives` 新增讀取事件數值的方法。數值大於 0 向上，小於 0 向下。
  - 滑鼠在格子按鈕上時，滾輪事件由按鈕接收。所以面板與 30 格都註冊滾輪事件。
  - 篩選或排序改變後，頂列限制在合法範圍內。捲動後，重新計算滑鼠所在格子的說明。
- 說明框（浮動 Tooltip，使用者決定，2026-11-05）：
  - 標準化為通用元件，放在 `src/shared/ui/`（`@shared/ui`），之後其他介面也使用它。它只接收文字行、目標範圍與可見範圍，不含任何遊戲規則。知識的文字（等級、經驗等）由面板產生。
  - 整個螢幕的可見範圍計算（`visibleScreen`）也放在 `@shared/ui`。
  - 物品欄的固定說明框不在本設計中改變。
  - 滑鼠移到格子上時顯示，離開格子、捲動到空格或關閉面板時隱藏。
  - 只建立一個 Tooltip 框架，移動它的位置，不為每格建立。
  - 寬度固定，高度隨文字自動調整：文字框架只設定寬度，背景以文字的四角加上邊距定位。
  - 位置以格子為準，不追蹤滑鼠座標（WC3 沒有可靠的本地滑鼠螢幕座標）：
    - 水平：放在格子右側。右側超出可見範圍時，改放左側。
    - 垂直：格子在畫面上半部時，Tooltip 頂端對齊格子頂端，向下延伸；在下半部時，底端對齊格子底端，向上延伸。這樣不需要知道 Tooltip 的高度。
  - 位置的計算是純函式（輸入格子位置、可見範圍、Tooltip 寬度，輸出對齊點），在 Node 中測試。
  - 內容：名稱、節點類型、主要歸屬法則、知識深度、等級、經驗與說明。
  - 經驗顯示**本級進度／本級所需**：
    - 解析中：`35.0／100`。
    - 已形成：例如 150 經驗（1 級）顯示 `50.0／200`。
    - 最高等級：顯示「已達最高等級」。
- 篩選（按鈕循環切換）：
  - 節點類型：全部、核心、型態、效果、修飾、觸發、橋接。
  - 法則：全部、七大法則。
  - 狀態：全部、已形成、解析中。
- 排序（按鈕循環切換）：
  - 名稱：以字串的 `<` 比較（Lua 與 JS 對 BMP 中文的結果相同）。
  - 等級：等級高到低；等級相同時經驗高到低。
  - 節點類型、法則：依 `config/` 中固定的順序陣列。
  - 以上全部同值時，以目錄編號排列，結果穩定。
- 只顯示經驗大於 0 的知識。
- 測試指令：
  - `-know`：開關視窗。
  - `-know-exp <目錄編號> <經驗>`：把累積經驗**設定**為指定值（不是增加）。
    - 編號只接受目錄已定義的編號（目前 0～6）。保留位置不接受。
    - 經驗只接受 0～4000，最多一位小數。先檢查字串格式與範圍，再以字串拆成整數與十分位轉為單位，不使用浮點數乘法。
    - 編號 0 與經驗 0 都有效。以明確比較判斷，不使用真假值。
    - 拒絕時顯示用法，不改變狀態。
  - `-know-fill`：開關測試模式。打開時，視窗加入 40 項只用於顯示的假知識，用於在遊戲內驗證捲動、末列與篩選。假知識不保存，不影響 `Hero.knowledge`。

### 圖示

每種節點類型使用一個遊戲內建圖示（`ReplaceableTextures\CommandButtons\` 中的 BTN 圖示）。圖示路徑放在 `config/`，之後可以替換。

## 不包含

- 研究、學習、碎片、聯想線索。
- 知識圖譜（研究前置的連線）。
- 精通與法則。
- 從 `docs/dnd/知識/` 自動產生全部知識頁的目錄。
- 隱藏內建面板（`hideOrigin`）與替代介面（頭像、生命與法力、技能按鈕、小地圖等）。使用者決定遊戲開始就永久隱藏，這會影響全部遊戲操作，所以另立設計稿（暫定 `docs/custom-hud/`）。本設計只確保知識面板在兩種情況下都能使用。
- 既有程式的常數改名為大寫蛇形命名法（AGENTS.md，2026-11-05）。使用者決定另外安排一次改名。本設計的新常數已使用新規則（例如 `KNOWLEDGE_CATALOG`）；`heroKnowledge`、`maxPackedBytes` 等既有名稱暫不改變。
