# 英雄與裝備存檔實作

唯一規格為 `../PLAN.md`。本次實作 S1 至 S3。S4 由使用者執行，不啟動遊戲。

## 做法

- 存檔提供通用參與者。沒有參與者時保留版本 2，維持既有呼叫與測試。
- 有參與者時建立版本 3。版本 2 轉換時使用參與者的固定空資料。
- app 提供英雄與裝備兩個參與者。英雄參與者先驗證並暫存純資料；裝備參與者使用此資料驗證穿戴。全部成功後才恢復英雄與範例資料。
- 編碼與解碼使用純函式。解碼從預建英雄重新升級，再以保存的知識驗證裝備。
- Node 與 Lua 共用驗證案例。另用 NumberAudit 檢查整數及 float32 精度。

## 與設計稿不同的地方

- 目前目錄沒有工具類物品。滿裝備測試使用主武器、副手、防具，工具位置為空。保留規格目錄與欄位，不新增物品。

## S4 遊戲內驗證

1. 開啟建置地圖。以 `-hero`、`-items` 記錄初始狀態。
2. 以 `-hero-up` 升級，並以 `-item-new`、`-equip` 換裝。記錄 `-hero`、`-items` 的數值、詞綴與清單順序。物品編號不作相同比較。
3. 輸入 `-save`。關閉並重新開啟地圖。輸入 `-load`。
4. 比較 `-hero`、`-items`。數值、詞綴、穿戴位置與持有順序必須相同。編號依穿戴位置與持有順序重新配置。
5. 修改存檔碼的一個有效字元，再以手動完整碼或分段指令讀取。必須顯示「存檔碼無效」，英雄、裝備與範例資料不變。
6. 輸入同名玩家的版本 2 存檔碼。範例資料必須恢復，英雄與裝備不變。
7. 在失能時讀取英雄存檔。生命維持 0，復起後使用恢復後的上限。
8. 以其他玩家存檔，確認沒有英雄資料。多人用戶端須得到相同狀態。
