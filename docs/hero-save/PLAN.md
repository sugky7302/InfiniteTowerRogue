# 英雄與裝備存檔

## 目的

- 把英雄（職業等級、知識）與裝備（4 個穿戴位置、12 件持有清單）加入存檔碼。
- 讀檔後恢復同一英雄與同一批物品。數值重新計算，不保存計算結果。

## 來源

| 主題 | 來源 |
|---|---|
| 存檔格式、編碼、版本轉換 | `docs/save-system/PLAN.md`、`.github/skills/save-system` |
| 英雄、物品、穿戴規則 | `docs/hero-item-attributes/PLAN.md`、`.github/skills/hero-item-attributes` |

## 決策

| 問題 | 決策 |
|---|---|
| 一級屬性 | 不保存。讀檔時從預建英雄開始，依保存的職業等級重新執行 `levelUp`。原因：位元較少，且屬性與等級不會不一致 |
| 物品實例編號 | 不保存。讀檔時依順序重新指定 1、2、3…，範例的下一個編號接續 |
| 物品與詞綴 | 以目錄索引保存基底、階級、詞綴與詞綴值。不保存名稱或字串 |
| 無效的存檔內容 | 驗證全部內容後才套用。任一項失敗時，整份存檔不套用，只顯示「存檔碼無效」 |
| 舊版存檔（版本 2） | 轉換時英雄區段為「沒有資料」。讀取後只套用範例資料，英雄與裝備不變 |
| 持有清單 | 保存順序。讀檔後順序相同 |

## 模組位置

存檔功能（`features/save`）不得 import 英雄或裝備（同層規則）。存檔只提供通用的「參與者」介面。英雄的欄位對應放在 app。

| 位置 | 內容 |
|---|---|
| `src/features/save/model/participant.ts`（新） | `SaveParticipant` 介面 |
| `src/features/save/model/demo.ts` | 版本 3：範例區段＋參與者區段；版本 2 增加 `migrate` |
| `src/features/save/model/chat.ts` | `-save` 收集參與者資料；讀檔時先驗證全部參與者，再一起套用 |
| `src/app/hero-save.ts`（新） | 目錄、區段定義、英雄與裝備的編碼及解碼（純函式） |
| `src/app/hero-example.ts` | 新增讀取快照與恢復狀態的方法 |
| `src/main.ts`、`src/app/save-example.ts`、`src/app/skill-example.ts` | 組合：技能範例傳回英雄範例，存檔範例接收參與者 |

## 參與者介面

```ts
export interface SaveParticipant {
    readonly section: SaveSection;
    /** 舊版轉換時使用。必須是常數，不得讀取遊戲狀態。 */
    readonly empty: Record<string, SaveValue>;
    /** 共同流程。傳回 undefined 時存檔失敗。 */
    collect(player: player): Record<string, SaveValue> | undefined;
    /** 共同流程。只驗證，不修改狀態。成功時傳回套用函式。 */
    prepare(player: player, values: Record<string, SaveValue>): ((this: void) => void) | undefined;
}
```

- 讀檔流程：解碼 → 全部參與者 `prepare` → 任一傳回 undefined 時顯示「存檔碼無效」→ 否則執行全部套用函式，再更新範例資料。
- 參與者在全部用戶端執行相同步驟。資料來源必須是同步狀態。

## 存檔格式版本 3

版本 3 的區段：`demo`（與版本 2 相同）、`hero`、`equipment`。

### `hero` 區段

| 欄位 | 種類 | 範圍 | 說明 |
|---|---|---|---|
| `present` | 布林 | | false 表示沒有英雄資料，讀檔時不改變英雄與裝備 |
| `preset` | 整數 | 0～15 | 預建英雄目錄索引 |
| `classIds` | 清單 ×4 | 0～15 | 職業目錄索引，0 表示空 |
| `classLevels` | 清單 ×4 | 0～63 | 職業等級，空位為 0 |
| `knowledge` | 清單 ×32 | 0～1 | 知識目錄的位元旗標 |

### `equipment` 區段

16 個物品位置：0～3 為穿戴位置（主武器、副手、防具、工具），4～15 為持有清單。

| 欄位 | 種類 | 範圍 | 說明 |
|---|---|---|---|
| `bases` | 清單 ×16 | 0～63 | 物品基底目錄索引，0 表示空 |
| `tiers` | 清單 ×16 | 0～3 | 物品階級索引（普通、精良、名品、傳世） |
| `affixIds` | 清單 ×64 | 0～31 | 每件物品 4 個詞綴的目錄索引，0 表示空 |
| `affixValues` | 清單 ×64 | 0～63 | 詞綴值，空位為 0 |

- 空的物品位置：基底、階級、詞綴與值都為 0。
- 預估大小：約 950 位元，存檔碼約 260 字元。手動分段約 4 段。

### 目錄（只能在尾端增加）

- 目錄定義在 `src/app/hero-save.ts`。索引 0 保留為空。已發布的索引不得改指向其他項目。
- 預建英雄：`[符文學者]`。職業：`["", 符文學徒]`。知識：`runeScholar.knowledge` 的 7 項，依目前順序。
- 物品基底：`["", 符文杖, 訓練短劍, 巡檢長槌, 術式手冊, 學徒長袍]`。階級：`[普通, 精良, 名品, 傳世]`。
- 詞綴：`["", ...affixes 依目前順序]`。

## 編碼與驗證

- 編碼失敗（傳回 undefined）：知識不在目錄、職業不在目錄、物品或詞綴不在目錄、職業超過 4 個、詞綴超過 4 個、持有清單超過 12 件。
- 解碼驗證（任一失敗即拒絕）：
  1. 預建英雄、職業、基底、詞綴索引都在目錄範圍。
  2. 職業不重複。職業必須是預建英雄已認證的職業。等級不低於預建等級，且不超過最高等級。
  3. 空的物品位置的其他欄位必須為 0。詞綴必須連續放在前面，數量等於該階級的詞綴數。
  4. 每件物品以 `getItemBonuses` 驗證（詞綴重複、相容、階級區間）。
  5. 穿戴物以 `equip` 依序穿上：主武器、副手、防具、工具。全部必須成功，且穿在保存的位置。
  6. 穿上時使用讀檔後的英雄知識。

## 範例的行為

- `HeroExample.snapshot()` 傳回英雄、穿戴物與持有清單。
- `HeroExample.restore(hero, worn, held)` 取代狀態，重新指定物品編號，再更新戰鬥登錄與血條。
- 只有擁有符文學者的玩家（玩家 1）有英雄資料。其他玩家的 `collect` 傳回 `present: false`。
- 失能中讀檔：沿用既有生命規則（失能維持 0）。

## 不包含

- 英雄位置、目前生命、技能冷卻、法力。
- 新職業認證、屬性點分配（目前沒有此規則）。
