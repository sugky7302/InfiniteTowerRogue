最終檔已通過 World Editor **SD 模式**的開啟、描述修改、另存及重開。尚未進行遊戲測試。不要把編輯器顯示正常視為職業、攻城或多人系統正常。〔S1〕

## 遊戲類型與核心循環

**文字資料：** 地圖自述為「攻城對戰＋角色扮演」，並標示約一至兩小時的遊戲時間。這是地圖作者的描述，本文沒有實測時長或完整攻城勝負流程。〔S3〕

**設計推論的核心循環：** 初心者練等 → 選擇職業 → 取得技能與裝備 → 探索新地區或參加事件 → 合成、插卡與精煉 → 二轉或轉生 → 挑戰更高壓力內容。職業門檻與系統存在有資料支持；整段流程尚未逐步遊玩確認。

## 地形與空間設計

**影像觀察：** 本圖小地圖的中央與右側包含較大的連續野外。左側、上緣與下緣有多個分隔區塊。黑色間隔使這些區塊在圖上形成獨立空間。它們的實際用途仍須對照區域與傳送腳本，不能只憑外觀命名。〔S10〕

**腳本與文字資料：** 已找到職業轉換區、轉生區、城鎮事件生成區及傳送門目的地。這些資料支持「主要世界加上分隔服務區」的配置。〔S3、S7、S8〕

**設計推論：** 分隔區可容納轉職、事件或特殊戰鬥，減少不同活動互相干擾。代價是玩家較難記住位置，也可能在傳送後失去方向。

**改作提案：** 爬塔可使用一個休息大廳連接數個戰鬥房。每個出口顯示目的地、危險等級與是否能返回。進房時顯示房間名稱。把入口安全區與敵人生成區分開。多人傳送需處理有人死亡、斷線或仍在上一房的情況。

原圖已恢復 369 個靜態區域與 12,939 個裝飾物。數量只代表內容規模，不代表值得照抄。先用少量房間驗證走位和辨識度，再增加景觀。〔S1〕

## 三個技能設計案例

### 一、治癒術：同一操作對不同對象有不同用途

**文字資料：** 治癒術說明可恢復玩家生命，也可傷害不死系敵人。文字列出技能等級與智力對恢復量的影響。本文沒有逐項追完治療與傷害公式。〔S11〕

**可參考之處：** 支援角色在缺少受傷隊友時仍有事可做。敵人分類也會影響技能選擇。

**改作提案：** 使用目標陣營與分類來決定效果。友軍接受治療，不死敵人接受傷害，其他敵人則拒絕施放。游標與說明要預告結果。不要讓同一種圖示在沒有說明時突然傷害玩家。

### 二、暴風雪：持續區域與控制機率

**文字資料：** 主動技能說明包含範圍水屬性傷害、多波攻擊與冰凍機率。〔S12〕

**腳本確認：** 另有自動施法用的暴風雪循環。它搜尋範圍內單位、施加傷害、依機率觸發冰凍，並在完成後清除暫存資料。這能支持「週期範圍效果」的實作參考，但不能把此分支的全部參數直接當成主動技能參數。〔S13〕

**改作提案：** 將傷害區域、顯示區域與控制效果分開。以一個固定週期處理區域內目標。施法者死亡或房間結束時要終止循環。為首領設控制抗性，避免多個玩家將它永久冰凍。

### 三、阿修羅霸凰拳：把儲備資源換成爆發

**腳本確認：** `A01G` 的處理先讀取力量與目前魔力。基礎計算使用力量乘以整數化的魔力級距。後續還有裝備與狀態分支。造成傷害後會把施法者魔力設為零。這不是最終傷害的完整公式。〔S14〕

**設計推論：** 玩家要在立即施放與繼續累積資源之間選擇。施放後的低資源狀態形成代價。

**改作提案：** 用一條可見的專注值支援重擊。施放預覽顯示預估效果與消耗。先決定施法被打斷時是否扣資源，再測試死亡、無效目標及反覆按鍵。可限制對首領的峰值，保留一般戰鬥的爆發感。

## 裝備設計與資料結構

插卡與精煉會共同影響同一件裝備。現有腳本因此需要在替換物品時保留精煉、所有權或其他連結。這是值得學習的資料一致性問題。〔S5、S6〕

**改作提案：** 每件裝備保存 `itemId`、`ownerId`、`baseType`、`refineLevel` 與 `socketIds`。顯示模型不應當成裝備身分。所有屬性加成由一個計算入口重算，避免穿脫、插卡與倉庫移動各自加減而累積誤差。

精煉流程可分成五步：驗證角色與物品 → 驗證材料 → 計算結果 → 一次更新裝備與材料 → 顯示結果。失敗若代表機率失敗，仍按規則消耗材料；失敗若代表系統無法完成，則不扣材料。這個區分必須寫進規格。

## 介面與節奏

原圖有 F9 說明、聊天指令、升級提示與小地圖標記。這些入口可讓大量系統被找到，但也提高學習負擔。〔S3、S9〕

**改作提案：** 在爬塔遊戲中，把轉職、插卡、精煉放進休息房。戰鬥中只保留技能與少量道具操作。提示採用「已達成條件、可做的操作、目的地」三段。將完整規則留在可重開的說明頁，不用長訊息阻擋戰鬥視線。

## 適合先做的原型與驗收

以下均為**改作提案**。

1. 做一個初始職業與兩條專精。確認分支改變操作方法，而非只換傷害倍率。
2. 做三件裝備與三張卡片。測試插卡後穿脫、放入倉庫與再次取出，確認屬性不重複增加。
3. 做一個精煉服務。測試材料不足、背包已滿、無效裝備與連續點擊。確認每次只更新一次。
4. 做一個大廳與兩個戰鬥房。確認死亡、回程與全隊傳送都不會把角色留在封閉區。
5. 做一個事件房與三級引導：觸發時提示、地圖標記、結束結果。確認獎勵只發一次。

先完成職業分支、裝備一致性與場景切換，再增加轉生或攻城。攻城需要另外定義陣營、基地、勝負、重生與離線處理，本文目前只有類型文字，沒有足夠證據寫成完整攻城規格。
