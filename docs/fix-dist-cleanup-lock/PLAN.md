# 修正輸出資料夾清理失敗

## 問題

- 測試指令在刪除 `dist` 時發生 `EPERM`，因此未進入編譯階段。
- Windows 程式若持有資料夾控制代碼，可能阻止刪除該資料夾。
- 遊戲或編輯器若持有輸出檔案，仍可能阻止更新該檔案。

## 修改

1. 保留 `dist` 資料夾，只清除其中的舊建置內容。
2. 對暫時的檔案占用進行有限次重試。
3. 清理失敗時，顯示受影響路徑與解除占用的操作方式。
4. 保留原始地圖及 `src/`。不強制關閉遊戲或編輯器。

## 驗證

- 重現其他程序使用 `dist` 作為目前資料夾時的清理情況。
- 驗證修正後可在相同情況下完成清理及建置。
- 驗證輸出檔案被獨占時，流程停止並顯示明確訊息。
- 比對原始檔案內容，確認未被修改。

## 限制

- 持續占用的檔案必須由使用者關閉相關程式後，才能更新。
- 清理與建置成功不能取代遊戲內測試。

## 驗證結果

- 獨占讀取檢查確認，先前的 `dist/bin/map.w3x` 正被其他程序使用。使用者關閉遊戲後，建置成功。
- `node scripts/check-build-cleanup.cjs` 通過。測試以另一個程序持有輸出根目錄，重現直接刪除根目錄失敗，並確認修正後可清理內容。
- 同一測試以 Windows 檔案控制代碼阻止刪除，確認持續占用時會顯示解除占用的操作提示。釋放控制代碼後，清理成功。
- 建置與測試腳本的 TypeScript 型別檢查通過。
- `npm.cmd run build` 與 `npm.cmd run test` 均完成清理、編譯及封裝。測試流程已實際進入遊戲地圖。
- 封裝腳本與建置資料夾內容一致。原始地圖及 `src/` 的 19 個檔案雜湊未變更。
- 清理使用 Node.js 的有限次重試設定。參數說明請參考 [Node.js 檔案系統文件](https://nodejs.org/api/fs.html#fsrmsyncpath-options)。
