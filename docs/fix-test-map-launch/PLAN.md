# 修正測試地圖啟動流程

## 問題

- 使用者執行 `pnpm run test` 後，遊戲停在主畫面。
- 現有測試流程只編譯資料夾，沒有建立封裝地圖。
- 測試流程會清除 `dist`，因此會刪除上一次建置的封裝地圖。
- TypeScript 產物只合併到 `war3map.lua`，不會出現在觸發編輯器。

## 修改

1. 提供共用的建置函式，讓建置與測試使用相同的封裝流程。
2. 測試時傳入封裝地圖的絕對路徑，並加入 `-editor` 參數。
3. 啟動失敗或建置失敗時，回報錯誤並設定失敗狀態。
4. 保留原始地圖與 TypeScript 程式。補充編輯與測試方式。

## 驗證

- 執行建置，確認封裝檔存在。
- 重新讀取封裝檔，確認地圖腳本與建置資料夾一致。
- 確認原始地圖內容未被修改。
- 執行測試流程並檢查遊戲畫面。只有看到地圖與程式效果，才記錄遊戲驗證通過。

## 限制

- Lua 語法檢查與封裝檢查不能證明遊戲載入成功。
- 不將 TypeScript 產物寫入觸發編輯器。編輯器存檔後，必須重新建置。

## 驗證結果

- 使用 `npm.cmd run build` 執行相同的建置腳本，成功產生 `dist/bin/map.w3x`。
- 使用 `npm.cmd run test` 執行相同的測試腳本，確認傳入封裝檔的絕對路徑與 `-editor` 參數。
- 遊戲實際進入地圖。移動鏡頭後，看到原點附近由 TypeScript 程式建立的步兵。此單位不在原始地圖的預放單位腳本中。
- 重新讀取封裝檔，取得 20 個檔案名稱。抽查地圖腳本、地圖資訊、地形及兩個觸發器資料檔案，內容皆與建置資料夾相同。
- 確認遊戲腳本等於原始地圖腳本與 TypeScript 產物的合併內容。
- 比對 `source-hashes.json` 中的 19 個原始檔案，內容皆未變更。
- 使用 TypeScript 檢查兩個建置與測試腳本，型別檢查通過。
- 尚未分別測試封裝方式與 `-editor` 參數的影響，因此不將載入失敗歸因於單一因素。

`-editor` 參數的使用方式亦可參考 [WurstSetup 的測試流程說明](https://github.com/wurstscript/WurstSetup#running-your-project-in-warcraft-iii)。
