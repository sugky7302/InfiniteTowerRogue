# RxWC3 M5 整合範例計畫

本計畫依 `../PLAN.md` 與本次任務實作。不新增核心 API、套件或 Git 提交。遊戲內驗證須由使用者完成。

## 設計

1. 新增 `wc3/m5-example.ts`。只替換 `main.ts` 的 M4 import 與 hook，保留既有範例及使用者註解。
2. 將可測試邏輯放在 `wc3/m5-logic.ts`。`whenCastCompleted` 使用獨立 `pipe`，組合 `switchMap`、Combat 階段的世界時鐘 `timer`、`takeUntil` 與 `map`。注入事件來源及時鐘，預設使用正式來源。施法結束會取消預告；新施法會取代舊預告。
3. 英雄與首領使用暴風雪作為原生引導載體，停用原生傷害。預告分別為 0.8 秒與 1.5 秒。預告完成才由範例造成 40 點傷害。作用後等待 0.4 秒收招，再下達停止命令。各階段輸出世界時間；中斷不執行作用。
4. 目標的護盾初值為 100。第一個傷害訂閱將傷害乘以 2；第二個訂閱以 Signal 護盾吸收正傷害。兩次作用預期為 `40 → 80 → 0` 與 `40 → 80 → 60`。以 computed 衍生耗盡狀態，以 effect 輸出耗盡訊息。所有修改同步執行。
5. 全部頂層訂閱、Signal effect 與排程在共同啟動流程建立，由同一個 Subscription 收集。operator 的內層訂閱由 switchMap 管理。沒有本地分支。
6. `-pause` 與 `-resume` 使用世界時鐘引用計數。範例另外記錄自己持有的暫停次數，避免釋放其他系統的暫停。示範單位也暫停；這是範例的戰鬥層工作，並非 RxWC3 的職責。介面時鐘每秒輸出狀態。
7. 自動流程展示英雄成功、首領成功及英雄中斷。`-m5-cast` 可重播英雄施法，`-m5-boss` 可重播首領施法，方便在啟動流程之後測試暫停。每次下令前重設載體冷卻與魔力。
8. `-m5-stop` 取消全部訂閱與 effect、釋放範例持有的暫停、清理範例單位及預告效果。先取消事件與任務，再清理單位。停止後不再輸出介面狀態。初始化失敗也執行相同清理。錯誤使用 logger。

## 遊戲內驗證

使用者執行 `npm run test`。下表時間以範例啟動後的世界時間差為準，原生施法可能增加少量延遲。

| 步驟 | 預期輸出及行為 |
|---|---|
| 啟動 | 顯示「M5 已啟動」及護盾 100。M4 不再啟動。 |
| 約第 2 秒 | 英雄顯示準備；0.8 秒後顯示作用，增傷 `40 → 80`，護盾吸收 80、剩餘 20、傷害 0。再過 0.4 秒顯示收招完成。 |
| 約第 5 秒 | 首領顯示準備；1.5 秒後顯示作用，增傷 `40 → 80`，護盾吸收 20、剩餘 0、傷害 60，顯示護盾耗盡。再過 0.4 秒顯示收招完成。 |
| 約第 9 秒 | 英雄再次準備；0.2 秒後下達停止命令，顯示中斷。之後不得出現這次施法的作用或傷害。 |
| 每秒 | 顯示介面時間、世界時間與暫停次數。 |
| 輸入 `-m5-boss`，準備時輸入 `-pause` | 顯示暫停時的 worldClock.now()。等待數秒，世界時間不變、沒有作用；介面時間持續增加。 |
| 再輸入 `-pause`，然後輸入一次 `-resume` | 暫停次數從 2 減至 1。世界時間仍不變。 |
| 再輸入 `-resume` | 暫停次數變成 0。世界時間前進，依預告剩餘秒數完成，並非重等 1.5 秒。 |
| 準備時輸入停止命令 | 顯示中斷。預告到期後沒有作用。 |
| 暫停或準備時輸入 `-m5-stop` | 顯示取消確認。範例單位與預告效果移除，範例持有的暫停釋放。等待超過數秒，不再有介面、作用或護盾輸出。聊天指令也不再處理。 |

Node 與 Fengari 不能取代 WC3 的原生施法、傷害、單位暫停及 float32 驗證。M5 的遊戲完成條件在使用者確認前保持未完成。

前兩次成功作用的詳細訊息如下。第一次的 `onDamaged` 可能不送出零傷害事件，因此不以零傷害後事件作為通過條件。第二次應顯示「M5 傷害後：60，護盾 0」。原生顯示的數字可能含 `.0`。

```text
M5 增傷：40 → 80
M5 護盾：傷害 80，吸收 80，剩餘 20，傷害傳出 0
M5 增傷：40 → 80
M5 護盾：傷害 80，吸收 20，剩餘 0，傷害傳出 60
M5 護盾耗盡。
```

首領也由玩家 0 控制，可選取後按下停止鍵，確認手動中斷。預告以目標點的提示模型表示；原生暴風雪保留動畫與聲音，但兩個原生傷害欄位都設為 0。實際傷害只在範例的作用階段執行。這是整合示範，沒有實作正式技能資料或攻擊範圍。

測試剩餘時間時，建議先等待自動流程結束，再輸入 `-m5-boss`。記錄準備與暫停訊息中的世界時間。恢復後，作用時間與準備時間之差應約為 1.5 秒；暫停期間經過的介面時間不計入其中。各原生命令成功訊息都應為 `true`。若命令失敗或沒有啟動訊息，須記錄錯誤，不可視為通過。

## 設計差異與核心限制

- 未修改 RxWC3 核心，沒有發現需要修正的核心缺陷。
- `whenCastCompleted` 表示「預告完成」，不代表 WC3 原生 `onSpellFinish`。它需要引導時間足夠長的技能；瞬發技能的結束事件會取消倒數。這是此組合的使用限制。
- 可測試函式只放在範例邏輯檔，不從 RxWC3 入口匯出，不新增核心 API。
- 與初稿的功能範圍相同。另加入 `m5-lua.spec.ts` 與 Lua 驗證工具擴充，以檢查 Lua 的 Signal 呼叫方式及事件組合。
- 首領使用可控制的大法師外觀。這可避免中立 AI 干擾，也讓使用者能手動停止施法。

## 尚未解決的問題

- 原生技能欄位能否停用全部暴風雪傷害、成功施法與中斷時序、實際傷害後的 60 點輸出，尚待遊戲確認。設定欄位失敗時會清理範例並由 logger 回報錯誤。
- `PauseUnit` 是否在目前遊戲版本保留引導狀態、恢復後的預告剩餘時間及原生動畫，尚待確認。世界時鐘本身只管理 RxWC3 任務，不管理單位、原生冷卻或其他遊戲系統。

### 暫停時預告中斷的原因

- 範例在暫停世界時鐘時，也用 `PauseUnit` 暫停單位。
- WC3 的 `PauseUnit` 打斷引導施法，並觸發施法結束事件。`takeUntil(onSpellEndCast)` 因此取消預告。
- RxWC3 沒有錯誤：世界時鐘已停止，引用計數正確。「暫停後依剩餘時間完成」已在 M2 的遊戲內驗證中通過（撤離倒數暫停 3 秒後於第 15 秒完成）。

### 對後續系統的影響

1. 戰鬥系統的戰術暫停不得用 `PauseUnit` 暫停引導中的單位，否則全部引導技能被打斷。替代方法須在戰鬥系統設計時於遊戲中驗證。
2. `whenCastCompleted` 只適用於引導型技能。瞬發技能在生效後立即觸發施法結束事件，預告會被取消。「發動後延遲」的預告須用 `onSpellEffect` 加 `timer`，並以失能或死亡作為取消條件。
3. 浮點數減法可能產生負零，顯示為 `-0.0`。顯示數值時須處理。
