# RxWC3 M2 實作計畫

本計畫以 `docs/rxwc3/PLAN.md` 與本次任務為準。只實作時鐘、排程器、時間來源與時間 operator。

## 設計

1. `Scheduler` 使用最小堆積。排序鍵為整數毫秒、結算階段、加入順序。取消時從堆積移除任務，並清除回呼。
2. 秒數四捨五入為整數毫秒。時間解析度為一毫秒。比較器使用整數，不使用可能破壞遞移性的誤差比較。`interval` 先將週期四捨五入，再將整數週期加到上次到期時間。回呼延遲不會改變後續到期時間。
3. `ClockDriver` 分開提供量時與單次喚醒。`start()` 重設量時基準，`stop()` 停止量時，`elapsedTicks()` 傳回整數毫秒。喚醒不得同步呼叫回呼。`Clock` 的保存時間、目前時間與到期時間都是整數毫秒。`now()` 只在輸出時換算為秒。
4. 沒有任務時仍計算閒置時間。取消最後任務只銷毀喚醒計時器。量時計時器繼續執行。只有時鐘暫停才停止量時。
5. 暫停使用引用計數。第一次暫停保存時間並取消喚醒。最後一次恢復才重新計時。多餘的 `resume()` 不改變狀態。
6. 同一次處理中，新增且已到期的任務加入堆積，於目前任務之後依排序執行。每次喚醒最多執行 10,000 個任務。超過時取消其餘已到期任務並回報一次錯誤。未到期任務保留。此上限允許大量正常任務，並阻止零秒自我排程阻塞遊戲。
7. 任務回呼使用 TypeScript `try/catch`。錯誤交給 `reportUnhandledError`，其他任務繼續執行。
8. `worldClock` 與 `uiClock` 不直接依賴 WC3。`installClockDriver(clock, driver)` 安裝驅動器。重複安裝會拋出錯誤。未安裝就排程也會拋出錯誤。Observable 訂閱會透過既有錯誤路徑傳遞此錯誤。
9. WC3 模組提供 `installWc3ClockDrivers()`。使用者須在地圖啟動時呼叫一次。本次只移除 `src/main.ts` 的數字探測匯入與 hook，保留 M2 範例 hook。模組載入不呼叫原生函式，所以 Node 可安全載入入口。安裝驅動器時開始量時，並建立量時計時器。
10. 每個執行中的 WC3 驅動器保留一個量時計時器，有任務時最多另用一個喚醒計時器。量時計時器每 60 秒讀取原生經過時間，換算為整數毫秒並加入整數基準，再重新啟動。讀取時間時，只換算本分鐘內的原生經過秒數，不累加浮點秒。喚醒最多等待 60 秒，再檢查整數到期時間，避免長週期浮點等待值損失毫秒精度。沒有任務時每分鐘一個維護回呼；有遠期任務時每分鐘最多另有一個喚醒回呼。世界與介面時鐘各自支付此成本。這是使用者同意的閒置量時修正。
11. 時間 API 使用 `{ clock?: Clock; phase?: Phase }`。預設使用 `worldClock` 與 `Phase.Default`。`throttleTime` 在相同物件額外接受 `leading` 與 `trailing`。預設分別為 `true` 與 `false`。
12. `delay` 等待全部值送出才完成。錯誤立即取消待送值。`debounceTime` 在來源完成時立即送出待送值。`throttleTime` 在啟用尾端送出時等待目前視窗結束，再送出待送值並完成。
13. 負數延遲視為零。非有限時間會拋出錯誤。`interval` 四捨五入後的週期至少為一毫秒，否則拋出錯誤。非整數毫秒週期依四捨五入後的週期運作。
14. 秒數輸入的絕對值上限為 2147483。整數毫秒上限為 2147483000，約 24.8 天。保留距 int32 最大值 647 毫秒的空間。秒數先拆為整數秒與小數秒，使用 Lua 整數乘法計算整數秒部分。加法先檢查剩餘容量，再相加。超過上限時明確報錯。週期排程在超過上限前送出錯誤並取消訂閱。長時間執行的應用須在此期限前建立新的時鐘。暫停期間不計入時鐘時間。
15. `now()` 在 WC3 仍傳回 float32 秒數。時間較大時，外部秒數顯示無法保留每個毫秒。內部相對排程、時間 operator 與 `interval` 直接使用整數毫秒，不經過 `now()` 的浮點輸出。

## 遊戲內手動驗證

1. 在測試地圖啟動時接入 `wc3/m2-example.ts` 的範例。啟動時只能呼叫一次。
2. 確認反向加入的任務仍依「傷害、撤離完成、潮封」輸出。
3. 確認第 5 秒取消的撤離不輸出完成值。
4. 確認另一個 12 秒撤離在第 15 秒完成。世界時鐘在第 5 秒暫停，於第 8 秒恢復。介面時鐘的第 6 秒訊息仍會出現。
5. 在兩次觸發間讀取 `worldClock.now()`，確認數值增加。暫停時確認數值不變。
6. 實際第 16 秒確認世界時鐘沒有任務，`hasWakeTimer()` 為 `false`，`hasTimer()` 仍為 `true`。實際第 18 秒確認世界時間約為 15 秒，並比第 16 秒增加約 2 秒。接著閒置暫停 1 秒，確認時間不變。恢復後確認時間繼續增加。
7. 使用 WC3 原生遊戲暫停，確認兩個時鐘均停止。恢復後確認倒數繼續。
8. 保持地圖執行，確認介面時鐘在第 1080 秒與第 7200 秒各輸出一個完成訊息。使用測試環境加速時，應以遊戲計時器時間比較。

遊戲內驗證由使用者執行。本計畫完成狀態保持 `false`。

## 接入方式

在地圖啟動時匯入 `@shared/rxwc3`，並呼叫一次 `installWc3ClockDrivers()`。此函式安裝兩個獨立驅動器，傳回 `{ world, ui }`。安裝時每個驅動器建立一個量時計時器。`hasTimer()` 檢查是否持有任何計時器，`hasWakeTimer()` 只檢查任務喚醒計時器。也可以使用 `new Clock(driver)` 建立自訂時鐘。

排程使用 `clock.schedule(秒數, 回呼, 階段)`。絕對到期時間使用 `clock.scheduleAt(秒數, 回呼, 階段)`。兩者傳回可取消的任務。呼叫 `task.unsubscribe()` 或 `clock.cancel(task)` 取消任務。`clock.pendingCount()` 傳回待執行任務數。

`Scheduler` 的底層到期時間單位為整數毫秒。一般使用者應透過 `Clock` 排程，並以秒為單位。底層整數 API 為 `nowTicks()`、`scheduleTicks()` 與 `scheduleAtTicks()`。

## 與原設計稿的差異

- 錯誤隔離使用本次任務指定的 TypeScript `try/catch`，不直接呼叫 Lua `xpcall`。
- 原版本未計算閒置時間。本次依使用者同意改為持續量時。閒置時保留量時計時器，暫停時才釋放。
- 暫停增加引用計數。這讓戰術暫停與選單暫停可以同時存在。
- 任務直接從堆積移除，不使用延遲刪除。取消時間為 O(log n)，且立即清除回呼。

## 尚未解決的限制

- WC3 的原生計時精度、原生遊戲暫停、計時器釋放與重新建立，尚待使用者在測試地圖確認。
- 既有 `subscribe` 多載會讓 TSTL 對物件形式的 `next` 箭頭回呼推導出 `self` 參數。Lua 測試使用 `next: function(this: void, value: number)` 明確指定呼叫方式。也可以使用 `subscribe(value => ...)`。本次未修改既有核心 API。
- 10,000 個任務上限觸發時，取消其餘已到期任務並回報錯誤。相應串流不會自動收到來源錯誤；呼叫端應透過共用錯誤處理器處理此排程失敗。
- `.cache/rxwc3/verify-lua.cjs` 是本次指定的驗證檔案，但 `.cache/` 已受現有 Git 忽略規則排除。本次已修改磁碟上的檔案，未修改忽略規則。

## 遊戲內實測與修正（2026-10-26）

下列資料由使用者在 WC3 Reforged 中取得。

| 項目 | 結果 |
|---|---|
| `math.maxinteger` | 2147483647，整數為 32 位元 |
| `math.type(2^31)` | float |
| `math.floor(12e6+0.5)` | 12000000，型別為 integer |
| `2^24 + 1 == 2^24` | true，浮點數為 float32 |
| `2^53 + 1 == 2^53` | true |
| `string.format("%.17g", 0.1+0.2)` | 0.30000001192092896 |
| `math.huge` | inf |
| `2^1024` | 0.0 |
| `Number.isFinite(12)` | true |
| 舊版 `toTicks(12)` | 拋出「時間必須是可表示為整數微秒的有限秒數。」 |

原因：TSTL 將 `Number.MAX_SAFE_INTEGER` 轉為 `2 ^ 1024`。WC3 將此算式算成零，使正常時間也被拒絕。微秒時間另有約 2147 秒的 int32 上限。舊版測試沒有長時間邊界案例，不能證明 WC3 可用。

修正：移除失效常數，使用明確的字面上限。時間改為整數毫秒。移除 `numberProbe.ts` 與其接入。保留使用者原有註解與 M2 範例接入。掃描 `src/shared/` 全部檔案，失效常數只出現在原時間換算與已刪除的探測程式；logger 沒有其他此類常數。
